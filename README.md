# Карман

Домашний видеоархив для плейлистов YouTube. Сервис следит за списками, скачивает новые ролики на ваш компьютер и даёт к ним веб-доступ из локальной сети. Никаких облаков и подписок: файлы лежат на диске, база — рядом.

## Что умеет

- **Плейлисты YouTube.** Добавление по ссылке, периодическая проверка, ручной запуск проверки, включение и выключение слежения.
- **Скачивание до 1080p.** MP4 H.264 через `yt-dlp` и `ffmpeg`. Новые ролики ставятся в очередь автоматически, существующие — только по флагу при добавлении.
- **Общая лента.** «Все видео» собирает непустые открытые плейлисты всех пользователей. Скрытые плейлисты видит только владелец.
- **Аккаунты.** Открытая регистрация, первый созданный пользователь — администратор. Веб-сессия на HttpOnly cookie, для Android — токен `Authorization: Bearer`.
- **Лайки и дизлайки.** Лайк переносит файл в `saved` и снимает срок хранения. Дизлайк сразу удаляет файл с диска — без корзины.
- **Сроки хранения.** Видео без реакции живёт N дней после скачивания (по умолчанию 7), просмотренное без реакции — M дней (по умолчанию 1). Удаление необратимо.
- **История просмотров.** Бессрочная, с процентом просмотра, ссылкой на оригинал и экспортом в `.txt`.
- **Веб-интерфейс.** Тёмная строгая тема: крупные превью 16:9, иконочные действия, скрываемая боковая панель, страницы «Сохранённые» и «Загрузки».
- **Android.** Клиент на Kotlin + Compose: сервер и логин, лента с поиском, плеер, плейлисты, история, лайк/дизлайк, скачивание на телефон с уведомлениями.

## Быстрый старт (Docker)

Нужен Docker Desktop (Windows/macOS) или Docker Engine с Compose.

```bash
cp .env.example .env
# откройте .env и укажите папку с видео, например VIDEO_ROOT=G:/Video
docker compose up -d --build
```

Откройте `http://localhost:8095` или `http://<ip-компьютера>:8095` с телефона в той же сети. Первый зарегистрированный аккаунт становится администратором.

Файлы:

- `./data` — база SQLite, кэш yt-dlp;
- папка из `VIDEO_ROOT` — видео, она монтируется в контейнер как `/video`;
- `./secrets` — необязательный `cookies.txt`.

Остановить: `docker compose down`. Обновить после изменений: `docker compose up -d --build`.

## Cookies и проверка YouTube

Если YouTube отвечает «Войдите, чтобы подтвердить, что вы не робот», положите cookies в формате Netscape в `./secrets/cookies.txt` и перезапустите контейнер:

```bash
docker compose restart
```

Файл можно получить расширением браузера «Get cookies.txt LOCALLY» (экспорт youtube.com). Cookies — это доступ к аккаунту: не коммитьте их и не пересылайте.

Дополнительно можно поднять `bgutil-ytdlp-pot-provider` и указать его адрес в `YTDLP_POT_BASE_URL` — это помогает с PO Token. Если в контейнере доступен `deno`, yt-dlp использует его для JS-челленджей.

## Структура файлов

```
<VIDEO_ROOT>/
  users/<логин>/saved/        # лайкнутые видео, хранятся бессрочно
  users/<логин>/playlists/    # видео из плейлистов, живут по срокам
```

Имена файлов строятся из названия и YouTube-id, поэтому дубликаты не появляются. При удалении плейлиста удаляются и его файлы.

## Правила хранения

| Состояние | Что происходит |
| --- | --- |
| Лайк | Файл переносится в `saved`, срок хранения отключается |
| Дизлайк | Файл удаляется сразу, запись помечается `deleted` |
| Без реакции | Удаление через `retention_unwatched_days` после скачивания |
| Просмотр без реакции | Удаление через `retention_watched_days` после просмотра |

Сроки задаются каждым пользователем в «Настройках». История просмотров при удалении файла остаётся.

## Локальная разработка

Бэкенд:

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
set DATA_DIR=G:\SelfSpot\Karman\data
set VIDEO_ROOT=G:\Video
uvicorn app.main:app --reload --port 8095
```

Фронтенд (Vite проксирует `/api` на `127.0.0.1:8095`):

```bash
cd frontend
npm ci
npm run dev
```

Демо-интерфейс без реального бэкенда: `node tools/mock-api.mjs` (порт 8095, демо-данные и обложки YouTube). Скриншоты для обзора: `node tools/shots.mjs`.

Сборка фронтенда кладётся в `backend/app/static`, её отдаёт FastAPI:

```bash
cd frontend && npm run build
```

## Настройки окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_PORT` | `8095` | Порт на хосте (compose) |
| `DATA_DIR` | `/data` | База и служебные файлы |
| `VIDEO_ROOT` | `/video` | Корень видеоархива |
| `ALLOW_REGISTRATION` | `true` | Открытая регистрация |
| `SESSION_DAYS` | `30` | Срок жизни сессии |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс в интерфейсе и экспорте |
| `MAX_PARALLEL_DOWNLOADS` | `2` | Одновременных скачиваний (1–4) |
| `MAX_VIDEO_HEIGHT` | `1080` | Максимальное качество |
| `DOWNLOAD_RETRIES` | `3` | Повторы при сбое |
| `POLL_CHECK_S` | `30` | Как часто планировщик проверяет расписание |
| `YTDLP_COOKIES_FILE` | `/secrets/cookies.txt` | Cookies для yt-dlp |
| `YTDLP_POT_BASE_URL` | пусто | Адрес POT-провайдера |
| `LOG_LEVEL` | `INFO` | Уровень логов |

## API

Краткое описание эндпоинтов — в [API.md](API.md). Веб использует cookie-сессию, мобильные клиенты — заголовок `Authorization: Bearer <token>` из ответа `/api/auth/login`.

## Android

Клиент лежит в `android/` (Kotlin, Jetpack Compose, Media3, WorkManager).

**Что умеет**

- вход по адресу сервера и аккаунту, открытая регистрация;
- общая лента «Все видео» с поиском по названию и каналу;
- плейлисты и история просмотров;
- плеер 16:9 с токеном, продолжение прогресса в историю;
- лайк (сохраняет навсегда) и дизлайк (удаляет файл на сервере после подтверждения);
- явная кнопка «Скачать на телефон»: загрузка идёт в фоне через WorkManager с уведомлением и прогрессом;
- вкладка «На диске»: локальные файлы, воспроизведение без интернета, удаление долгим нажатием — только вручную;
- настройки: сервер, пользователь, статистика хранилища, выход.

**Установка**

Готовый APK публикуется в GitHub Releases по тегу `v*`. Скачайте файл `app-release.apk` на телефон, разрешите установку из неизвестных источников и откройте приложение. При первом запуске укажите `http://<ip-компьютера>:8096` (или ваш порт).

**Сборка**

```bash
cd android
./gradlew :app:assembleRelease
```

APK появится в `android/app/build/outputs/apk/release/`. Локально нужны JDK 17 и Android SDK 35; в CI это делает workflow `.github/workflows/android.yml`. Сейчас release подписывается отладочным ключом, чтобы APK устанавливался; для постоянных обновлений замените `signingConfig` на собственный keystore, сохранённый в секретах репозитория.
